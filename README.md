# LoRA fine-tuning for NL→SQL

A before/after fine-tuning delta you can reproduce in one command.

Fine-tune a small instruct model (Qwen2.5-0.5B-Instruct) with LoRA to specialise it on a retail
NL-to-SQL task, then measure how much execution accuracy actually moves on a held-out set.

A larger Colab-ready version (Qwen2.5-7B-Instruct with Unsloth QLoRA) lives in
`notebooks/train_unsloth_qlora.ipynb`.

---

## Key results

| Model | Execution accuracy | Delta |
|---|---|---|
| Qwen2.5-0.5B-Instruct (base) | **15.0%** (6/40) | — |
| + LoRA (r=16, 3 epochs, 64 examples) | **50.0%** (20/40) | **+35.0 pp** |

Numbers come from `eval/results.json`, generated by `src/eval_compare.py` at seed=42. Run
`python src/eval_compare.py` to reproduce.

Execution accuracy here means the generated SQL returns the same rows as the gold SQL, compared
order-insensitively. Exec errors dropped from 22 to 5 across the same 40 questions.

---

## What this demonstrates

- LoRA fine-tuning with `peft` and `transformers`, no proprietary training framework required.
- Evaluation by execution accuracy rather than string similarity. A query that looks nothing
  like the gold SQL can still return exactly the right rows, and string metrics punish that
  unfairly.
- A reproducible dataset: all 104 NL→SQL pairs are generated and validated programmatically
  against a seeded SQLite database, so nothing here is a hand-written metric.
- A deployment path that works: merged GGUF plus an Ollama Modelfile (`src/export_gguf.py`).
- A scale-up route: the 7B model and Unsloth QLoRA notebook are ready for a T4.

## Schema

```sql
products(product_id, name, category, price, stock_qty)
customers(customer_id, name, email, city, country, joined_date)
orders(order_id, customer_id, order_date, status)
order_items(item_id, order_id, product_id, quantity, unit_price)
```

Retail database: 20 products, 100 customers, 200 orders, ~600 order items (seed=42).

## Quickstart

```bash
git clone https://github.com/Mojtaba-Alehosseini/lora-finetune-sql.git
cd lora-finetune-sql
python -m venv .venv && .venv/Scripts/activate   # Windows
# or: python -m venv .venv && source .venv/bin/activate  # Linux/Mac
pip install -e ".[dev]"

# 1. Build dataset + validate all SQL
python data/build_dataset.py

# 2. Fine-tune (CPU, Qwen2.5-0.5B, ~30-60 min)
python src/train_lora.py

# 3. Evaluate before/after
python src/eval_compare.py --adapter-dir adapters/
```

## Files

```
data/
  build_dataset.py       — build sample.sqlite + train/heldout JSONL (validates all SQL)
  sample.sqlite          — retail database (20 products, 100 customers, 200 orders)
  train.jsonl            — 64 validated NL-SQL pairs (seed=42)
  heldout.jsonl          — 40 held-out pairs for evaluation

src/
  train_lora.py          — LoRA fine-tuning (peft + transformers, CPU-feasible at 0.5B)
  eval_compare.py        — before/after execution accuracy evaluation
  export_gguf.py         — merge adapters + GGUF export for Ollama

notebooks/
  train_unsloth_qlora.ipynb   — Colab T4 notebook: Qwen2.5-7B + Unsloth QLoRA

eval/
  results.json           — committed evaluation results (base vs fine-tuned)

tests/
  test_dataset.py        — all SQL executes, DB integrity, JSONL structure (18 tests)
  test_eval_utils.py     — extract_sql, exec_sql, rows_match, make_prompt utilities (22 tests)

model_card.md            — intended use, training data, limitations
```

## Reproducibility

- Seed: **42** throughout (dataset shuffle, training, eval)
- All SQL validated against `data/sample.sqlite` before being written to JSONL — no fabricated pairs
- Committed `eval/results.json` contains the real before/after numbers
- `python data/build_dataset.py` rebuilds the database deterministically

```bash
pytest -q   # 40 tests
```

## Scaling up (Colab)

The `notebooks/train_unsloth_qlora.ipynb` notebook runs Qwen2.5-7B-Instruct with:

- **4-bit QLoRA** via [Unsloth](https://github.com/unslothai/unsloth) (2-4× faster than vanilla peft on T4)
- Same dataset + prompt format
- Adapters pushed to Hugging Face Hub
- Optional GGUF export for Ollama

Runtime: ~45 min on Colab free T4.

## Deployment (Ollama)

ollama run nl-to-sql
